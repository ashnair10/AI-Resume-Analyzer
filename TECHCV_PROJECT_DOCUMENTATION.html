TechCV is an evidence-first resume analysis workspace for developers and technical professionals. It connects a target job description to evidence in a real PDF or DOCX resume, explains where support is strong or missing, and keeps AI-assisted recommendations grounded in what the candidate can defend.

01 · Product

What TechCV does today

The current product accepts one resume and one target job description, then returns a transparent, deterministic first pass. Gemini can optionally add a structured semantic review. TechCV's score is a learning and improvement aid—not a hiring prediction or commercial ATS score.

⌕

Resume analysis

Extracts PDF/DOCX text and available formatting metadata, then checks job-language coverage, sections, impact signals, and direct evidence.

⌁

Evidence-first matching

Surfaces resume lines for high-signal job terms and marks direct support as strong, moderate, weak, or missing.

✳

Optional Gemini review

Can decompose requirements, assess claims, suggest truth-preserving rewrites, and provide recruiter and interview perspectives.

Product principle

A missing keyword is a gap to inspect—not permission to invent a skill, metric, employer, certification, or outcome.

The analysis page presents the Role Evidence Score and readiness, an evidence map, ClaimCheck, an AI review when returned, and a trace/guardrail view. Gemini can be switched off for deterministic-only testing.

03 · Deterministic engine

Scoring that can be inspected

The local engine uses simple heuristics—not semantic matching—to identify frequent job terms, compare them with resume tokens, locate matching lines, and estimate resume quality signals.

Evidence strength
30%

15%
Section completeness
10%
Formatting / parsability
10%

Evidence labels

StrongModerate WeakMissing

Direct keyword matches are heuristic signals. They do not verify that the candidate's claim is true or establish semantic equivalence.

Readiness labels

Ready to apply Improve before applying Weak fit

These are generated from the deterministic score and evidence-strength thresholds. They are not a prediction of employer decisions.

Interpretation note

Keyword coverage and evidence strength are deliberately separate. Repeated terminology can raise coverage without proving meaningful experience.

04 · Optional AI

Gemini enhances the review; it is not required

Deterministic mode

  • Resume extraction and heuristic analysis
  • Role Evidence Score and requirement/evidence map
  • Subjective-claim and weak-support signals
  • No Gemini key or external model call required

AI-enhanced mode

  • Structured job requirement decomposition
  • Semantic evidence review and ClaimCheck
  • Strengths, gaps, recruiter scan, and interview focus
  • Truth-preserving rewrite suggestions with confirmation flags

The backend validates Gemini output against Pydantic response models. If the key is absent or a model call fails, the deterministic response remains available and the API exposes AI status/error metadata.

Truth guard

AI suggestions are recommendations, not automatically applied resume edits. Verify every suggested claim and confirm any added scope, ownership, metric, or technology.

05 · System design

Small, explicit application boundaries

TechCV/ ├── frontend/ Next.js, React, TypeScript, Tailwind, Motion │ ├── app/analyze/ Main upload and analysis workspace │ ├── components/ Analysis and UI components │ └── lib/ API client and response types ├── backend/ │ ├── app/main.py FastAPI health and analysis endpoints │ ├── src/ Resume parser, heuristics, Gemini schemas/review │ ├── core/ AI gateway, guardrails, logging, telemetry │ └── tests/ API and analysis tests ├── legacy/streamlit-app/ Preserved original CVAlchemy application ├── docker-compose.yml Optional two-service container setup └── TECHCV_PROJECT_DOCUMENTATION.html

Frontend

Next.js App Router and React client UI. Sends a multipart request with the resume, job description, AI preference, and an x-trace-id.

Backend

FastAPI parses PDF/DOCX, runs the deterministic engine, inspects job-description signals, and optionally calls the AI gateway.

AI gateway

backend/core/ai_gateway.py is the provider boundary for Gemini today and a future location for routing or provider integrations.

Observability

Structured logs include request trace metadata. FastAPI OpenTelemetry instrumentation is opt-in with OTEL_ENABLED=true and an optional OTLP endpoint.

06 · API

Current local API contract

MethodRoutePurposeCurrent behavior
GET/healthService healthReturns service name, status, and version.
POST/api/analyzeAnalyze a resume against a job descriptionMultipart: resume, job_description, optional use_ai; trace via x-trace-id.
GET/docsInteractive API referenceFastAPI-generated OpenAPI documentation.

Validation and response outline

  • Accepts filenames ending in .pdf or .docx.
  • Rejects job descriptions shorter than 80 characters.
  • Rejects uploaded files larger than 8 MiB.
  • Returns a clear 422 response if the document contains no extractable text (for example, a scanned PDF without OCR).
  • Response groups include trace_id, timing, document metadata, guardrail signals, deterministic analysis, AI metadata, and optional ai_review.

07 · Trust & operations

Privacy, guardrails, and current limitations

What is in place

  • Local deterministic analysis works without a model key.
  • Lightweight email/phone and prompt-injection phrase checks run on the job description.
  • Trace IDs connect the frontend request with API response and structured analysis logs; the current log context includes the uploaded filename, so treat logs as operational data.
  • OpenTelemetry export is disabled unless explicitly configured.

Important boundaries

  • Guardrail checks are lightweight signals, not comprehensive PII redaction or security filtering.
  • Resume text is sent to Gemini when AI review is enabled and a Gemini key is configured.
  • Deterministic matching is keyword-based; it does not perform embeddings or semantic retrieval.
  • Scanned-image OCR, generated resume exports, accounts, and persistent analysis history are not in this build.
Use real candidate data carefully

The current local app is a development/demo implementation. Configure a trusted model provider, secure secrets, add robust privacy controls, and review deployment security before processing sensitive resumes in production.

08 · Developer setup

Run TechCV locally

Use separate terminals for the FastAPI backend and Next.js frontend. The commands below are for Windows PowerShell; activate the backend virtual environment before installing packages.

Backend

cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
uvicorn app.main:app --reload --port 8000

Frontend

cd frontend
npm install
Copy-Item .env.local.example .env.local
npm run dev

Open http://localhost:3000/analyze for the workspace and http://localhost:8000/docs for the API. The backend health check is http://localhost:8000/health.

Enable Gemini (optional)

# backend/.env
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-2.5-flash

Keep .env and .env.local files private. Without a Gemini key, switch off AI-enhanced review or use deterministic analysis; the core score and evidence map still work.

Optional: Docker Compose
Compose starts the API on port 8000 and web app on port 3000. Create backend/.env from backend/.env.example before starting because the API service reads that env file. Then run docker compose up --build from the repository root.
